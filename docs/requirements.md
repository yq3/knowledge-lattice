## 1. 项目定位

**一句话**：私有化部署的**企业知识层（通用平台）**——领域无关，首个落地场景为税务（属应用而非产品边界）；提供**文档知识**（知识库本体 + RAG 检索能力面）与**业务语义**（术语识别、业务对象及其关联——D23），以单一服务、单一 MCP server 提供给 Agent，**消费者以 Agent（deepagents）为主、人工检索测试为辅**。

四个定位要点：

1. **本质是知识库，不是 RAG 引擎**。核心资产是文档、权限、维度元数据与摄取管线（canonical 真相）；向量索引只是可重建的投影，检索配方是可替换的能力层。这决定了存储与治理优先于检索花活。
2. **agent 住客户端，知识库做工具服务器**（quivr V2 的反转姿态）：不在本系统内做 agent 循环、聊天界面、workflow 编排；把检索、溯源、鉴权做成值得 agent 信赖的 MCP 工具面。
3. **轻量自建，不做平台**。调研结论：开源五平台（ragflow/dify/anything-llm/quivr/kotaemon）的文档级权限全部缺位、面向人的产品面本需求用不上；自建薄服务可全部覆盖「检索质量 + 治理 + 工具面」三件事。
4. **知识层归一：文档知识 + 业务语义同服务（2026-10-18 D23 重定位，取代 2026-10-16「双层分立」口径）**。企业 agent 需要两类知识：**文档知识**（政策/操作指南等非结构化内容的语义检索与维度权限）与**业务语义**（术语识别 + 业务对象关联——概念/系统名词/场景/模板/模板字段/报表项/表/列组成的**类型化对象图**）。v0.4 曾将术语层定为独立的 glossary-agent MCP server（D17）；D23 将其并入本系统 `core/semantic/` 模块——**同一服务、同一 MCP server、同一套部署**，避免知识管理分散在多个服务。[glossary-agent](../../glossary-agent/) 项目转为调研与设计沉淀，其 AC 自动机精确匹配、三层渐进披露、Git YAML/PR 治理、四类黑话分治等结论是 semantic 模块的设计输入。**非目标（D23）**：GraphRAG（不用 LLM 抽取实体与关系、不生成社区摘要——关系本来就写在业务系统配置里）、图数据库（10⁴~10⁵ 节点、1~2 跳查询，SQLite 递归 CTE 足够）、元数据系统全量镜像（表/列只存轻量节点作关系端点，详情实时透传）。

性质与投入：lab 仓库 POC 先行，验证后拆仓演进；**全职投入**，MVP 预估 7~8 周（§8）；业务语义层按 M2 并行轨道（M2-S1~S3）推进，**不改变 M0a/M0b/M1 的冻结范围与节奏**（D23）。

## 3. 用户与场景

| 角色 | 说明 |
|---|---|
| 上传者 | 企业员工，经上传页面（或 agent 代传）投喂文档：先选知识库，再选数据维度，查看处理状态与质量报告 |
| 检索用户（人） | 经检索测试页做简单检索验证（上传后自查），可按知识库过滤；不是聊天问答界面。**同一用户可属多个组织**，在界面上切换组织（左上角），角色与维度授权随组织切换 |
| **Agent（deepagents）** | 企业内部独立部署的 agent 服务（LangChain 系），LLM 走企业内部网关；经 MCP 调用本系统，**代人检索**——请求携带所代表用户的身份 |
| 组织管理员 | 组织内管理知识库、维度定义、用户与维度授权；M2-S 起兼管语义层同步记录与冲突报告（`semantic:admin`） |
| 语义维护者（D23） | 业务/数据同学：经 Git PR 维护术语的别名、缩写、定义、口径、消歧说明与示例（FR-S2，每条必填 `owner`）；不手抄业务系统数据（源端事实自动同步）。过渡期（M2 前）即开始积累 YAML |
| 系统管理员 | 跨组织：创建组织、指定组织管理员 |

量级：数百用户；语料百万 chunk 以下（超出则走存储升级缝，见 NFR-5）。

核心场景流：

```
人工上传（选知识库 + 选维度）─┐
                    ├─→ 摄取任务队列 → worker：解析→切分→index_fts（词法先可搜）
agent 运行时凭证上传 ──────────┘         →嵌入（分批）→index_vec→质量检测
                              │（版本在用制：pending 完成后单事务切换 active）
                              ▼
人（检索测试页，可按库过滤）─┐   SQLite：元数据 + 五列 FTS + 向量BLOB + 维度/权限
                 ├─→ 检索管线：双路召回（维度 ACL 引擎内下推，仅 active 版本）
agent（MCP，带    │   + LLM 增强（800ms 并行，第三路 BM25）→ RRF → ACL 断言
委托 token/可信  │    → rerank → 二次断言 → 返回带 chunk_id 溯源 + 审计
子系统身份）─────┘
```

**层级模型（自上而下）**：组织（业务单元，各自一套维度定义与知识库）→ 知识库（业务分组与管理单元，**不承担权限**）→ 文档（权限挂点：维度标签 + owner）→ chunk。

## 4. 语料画像

- **语言三态并存**：纯中文、纯英文、中英混排的文档都有；用户 query 同样三态（含「中文问题带英文术语」的常见形态）。嵌入选型、分词、评测 judge 均按双语设计。
- **格式分布**（按占比从高到低）：纯文本/TXT、Excel、Word、PPT；PDF 少量（原生为主，**扫描件不多**）。
- **来源**：人工上传 + agent 上传；后续可能对接企业系统自动增量同步（演进项，初版不做）。
- **生命周期**：文档会更新——初版只支持人工重新上传覆盖（**内容哈希仅做重复提示、不拦截**，按 doc_id 显式覆盖重索引，见 FR-1）；删除同理。
- **上传纪律**：一份文件内的数据若分属不同数据维度，**拆成多个文档分别上传**（上传时各自选维度）。不做行级/块级权限（§7 决策 D4）。

## 5. 功能需求

优先级标注：〔M0〕骨架周 /〔M1〕核心能力 /〔M2〕生产化 /〔M2-S1~S3〕业务语义并行轨道（D23）/〔M3〕质量防线（对应 §8 里程碑）。

### FR-1 文档摄取〔M0 骨架，M2 生产化〕

- 上传接口：**三步凭证式（issue #32 P0-D）**——① agent 运行时（非 LLM）持委托 token 调 `POST /api/uploads` 声明 `{filename, size, sha256, content_type}` 获短时单次有效的 `upload_id/upload_url`（**绑定 sub+org+服务身份**）；② 运行时 PUT 文件字节（按声明 size 截断/拒绝、校验 sha256、全局上限 200MB）；③ LLM 调 MCP `upload(upload_id, ...)` 由知识库**校验 sub、org、服务身份三者一致且未过期、未使用、哈希匹配**（#34 4.3 统一口径，T11）后进摄取。**`file_ref` 不接受任意路径/URL**（SSRF 与任意文件读取防线）：确有共享存储场景走**白名单根目录 + realpath 规范化 + 前缀校验 + 只读 + 大小/扩展名限制**，不支持任意 URL 拉取。人经 REST 上传走 multipart 不受影响。上传时必选**知识库**与**数据维度**（必选维度，D5）。
- **文档身份**：`doc_id` 由系统生成（ULID）；**覆盖更新必须显式携带 `doc_id`**（不是按文件名/哈希猜"同一份文档"）；同库同维度下的相同内容默认提示重复、不强制拦截（去重键含库与维度，issue #31 P0-5）。
- 解析：**docling 为主**（进程内 Python 库；docx/pptx/xlsx/HTML 原生解析、结构输出完整）；扫描件走 **MinerU 懒加载**（按需部署 api_server，POC 阶段可不部署）。**M1 验证项**：TXT 的非 UTF-8 编码（GBK 等）识别与转换；`.doc/.xls/.ppt` 老格式明确策略（拒收提示转存新格式，不为此引入 LibreOffice——保零中间件）。
- 切分：结构感知（消费 docling 的标题层级/表格边界/页码）+ 递归 token（256–512）打底；**Excel 单列切分策略**（按 sheet/行块，**每个行块 chunk 重复表头**保留列语义）。
- 嵌入：bge-m3（多语，覆盖中英三态），进程内推理；**模型版本钉死并记录在每个 chunk 上**（embed_model 字段）。
- **摄取阶段拆分（issue #31 P0-4）**：`parse → chunk → index_fts（chunks+FTS 同事务，文档即刻可被 BM25 检索）→ embed（分批）→ index_vec（逐批写向量）→ quality`——各阶段幂等可续；文档状态细分 `searchable_lexical`（词法可搜）与 `searchable_full`（向量就绪）；无向量 chunk 检索时自动只走 BM25 路（RRF 退化为单路）。
- **版本替换与在用版本（issue #32 P0-A / #33 P0-2 闭环，v0.4）**：文档拆分「在用版本 `active_version/active_status/active_error`」与「处理中版本 `pending_version/pending_status/pending_error`」——**任意时刻检索只见在用版本的块**（召回 SQL 强制 `version = active_version AND tombstone = 0`），新旧版本绝不同时可见；版本切换单事务完成（含 `pending_dims_json → document_dimensions` 落库——**v2 的新维度在 pending 期间不生效**，切换前仍按 v1 维度判权限）。**切换时机（D20）**：首次上传允许 `searchable_lexical` 即切换在用；**覆盖上传必须等新版本 `searchable_full` 再切换**；新版本失败则 `pending_status=failed`、**失败块立即删除**（不留 FTS 残留）、旧版本不受影响。**并发与失败（v0.4）**：pending 期间再来的覆盖上传返回 **409**；删除文档即取消其任务（worker 每阶段开始前检查文档存在与版本归属）；embed 批次回写带防护（`tombstone=0 AND version ∈ {active, pending}`）；`pending_version = max(历史版本)+1` 不复用。PATCH 文档维度在 pending 期间返回 **409**。`fetch` 旧块返回 `{doc_id, active_version}` 替代提示（对象，不承诺块级映射）；旧版本块保留 90 天供审计回溯，切换时清空 embedding 与 FTS 列，到期物理删除。
- 异步任务化：解析/嵌入/入库不下同步链路；任务表 + worker 子进程（心跳、租约、重试、断点可续——ragflow 样板的最小化）。
- 原始文件与解析产物落本地对象目录（canonical 真相，索引可随时重建）。
- **文档更新与版本化（issue #31 P1-9 / #32 P0-A）**：覆盖更新 → 新版本走完管线 → 按 D20 切换时机单事务原子切换（见上文「版本替换」）；旧版本块置 tombstone 保留可查，agent 历史对话引用的旧 chunk_id 不失效为"不存在"——`fetch` 返回替代提示而非幻觉误判。
- agent 上传的内容标注来源（`source=agent:<id>`）并随检索结果返回来源字段（agent 代传内容可能携带持久化 prompt injection，高敏库可要求人工复核——issue #31 P2）。

### FR-2 检索与重排〔M1〕

- 双路召回：FTS5 BM25（jieba 预分词）+ 向量路（BLOB 距离函数，ACL 过滤后取 top-k）；召回窗口给足（参考口径：knn 1024 / **rerank 候选 32**——NFR-8），召回期不做用户阈值过滤。
- 融合：RRF（k=60，跨实现行业默认）。
- 重排：bge-reranker-v2-m3（进程内，同嵌入的 TEI 升级缝）；分数归一到 [0,1]、**喂 chunk 原文不喂分词文本**。
- 引用溯源：**稳定 chunk_id**（ULID，版本内不变；覆盖上传后 chunk_id 变化，`fetch` 以 `{doc_id, active_version}` 提示替代——工具输出自带溯源字段：chunk_id、doc_id、标题、页码、片段、分数）——agent 引用不存在的 ID 即幻觉证据。
- 查询变换：LLM 关键词增强（内部网关；对中英混合 query 的漏召回尤其有效）作为首个增强项；多查询扩展按评测数据决定是否加。
- 五列参与 BM25 加权：`title_seg ×3 / content_seg ×1 / keywords(仅人工词) ×5 / llm_keywords ×0.5~1 / tags ×8`（ragflow 加权模式 + issue #33 五列口径）。
- LLM 关键词增强：**800ms 硬预算、与原始召回并行执行**，超时丢弃；增强结果作为 RRF 的**第三路 BM25 查询**（不重做向量召回）。

### FR-3 区分度反馈环〔M1，用户明确要求进 MVP〕

- 入库时检测低区分度 chunk，两路信号、零 LLM 成本：向量拥挤度（新 chunk 与库内近邻的相似度分布，入库单块走 **SQL 暴力扫描**（量小），批量重算走 numpy 矩阵乘——见 §5.4/风险表）+ 词面通用度（token 平均 IDF，绝对阈值）。
- 自动兜底：LLM（内部网关）为低区分度 chunk 自动生成关键词 + 一句定位语，写入**独立的 `llm_keywords` 低权重列（0.5~1，进 FTS）**——只补 BM25 词面信号，非 Contextual Retrieval（后者重嵌入），表述如实。
- 人工兜底：上传完成页展示**聚合质量报告**（"N 个 chunk 建议补充标注"），点开可补、可忽略——不逐 chunk 打断，不强制。
- 用户标注落 `keywords`（仅人工词，×5）/`tags`（×8）列；**`keywords` 不混入 jieba 高频词**（高频词已在 content_seg，重复会被加权放大——issue #32 P1-3）。
- **重算策略（issue #32 P1-8）**：块检测时记录语料规模，重算覆盖「检测时语料规模 < 当前一定比例」的块（早期语料少时"通过"的块有漏报）+ 每周按比例抽样；近邻限定组织内。
- 前置 schema 动作：keywords/llm_keywords/tags/title_seg/content_seg 从 M0 起进表结构与 FTS5 索引（后补 = 重建索引）。

### FR-4 维度权限（核心差异化）〔M1 过滤生效，M2 管理面〕

- **模型**：文档级 ACL，维度模型（BI 行级权限 RLS 模式移植到检索层）：
  - 维度定义（dimension，含 `grant_source` 真值源声明）+ 取值枚举（dimension_value，**取值编码用企业主数据码**，如 ISO 国家码/税种码——issue #31 §4.7）元数据化，配置页面 CRUD；
  - 用户授权：用户 × 组织 × 维度 → 取值**集合**（多值）；
  - 文档维度：文档 × 维度 → **取值集合（多值，D19）**，上传时选择——通用政策可同时挂「中国区+海外区」而无需拆分上传；**内容混杂不同维度数据的文档仍须拆分上传（D4）**，多值只用于"内容通用、面向多个维度值开放"的场景。
- **过滤语义（D5+D19，v0.4 冻结复审修订——#34 必修 1 方案 A）**：文档可见 ⇔ 对**每个 `status='active'` 的维度**，满足「文档在该维度**无值 → 放行**，**有值 → 取值集合 ∩ 用户授权集合 ≠ ∅**」（维度间 AND、维度内 OR）。**维度生命周期与过滤彻底解耦**：`required` 只管上传校验、`enabled` 只管上传页展示——**都不影响过滤**；`retired` 是唯一退出过滤的状态（退役=唯一放宽路径，走退役权限事件：影响面预估 + 二次确认 + 审计）。**新增维度时零存量文档消失**（全空值放行），回填即逐篇收紧（上传页与管理页对空值文档提示"待补维度"）；必选改可选、停用均不放宽（T4/T20）。**无授权维度**（用户在某 active 维度授权为空集）→ 该用户只能看到该维度**为空**的文档（非整体不可见，T22）。
- **权限状态语义（P0-1，v0.4 保留）**：①授权行 `expires_at` 过期即失效（不等定时清理）；②取值 `status='disabled'` 视为"存在但无人被授予"（收紧）；③成员关系 `expires_at` 过期等同移出（检索时只过滤不删除，物理删除交定时任务触发级联清理；**续期已过期行被触发器禁止**——先删再加，防旧授权复活，T23）。
- **owner 兜底（v0.4 冻结复审修订——#34 必修 2）**：**检索路径无 owner 分支**（检索只有维度 ACL 一种语义）——彻底消除"授权撤销后 owner 借覆盖上传处理中窗口重新看到在用全文"的越权路径（T17/T21）；owner 经 `list_documents` 与文档详情接口查看自己文档的元数据与处理状态（管理面，不返回块内容）。
- **必选维度（已锁定）**：维度配置为必选时，上传强制选值，不留「未标注」歧义。
- **写权限（issue #31 P1-1 + #32 P1-4）**：上传与**修改文档维度（PATCH）**可打的取值都**限定在操作者本人授权集合内**（新旧取值均须校验——防把文档推向无权管理范围或"打自己看不见的值"）；超出范围的标注走 org_admin 审批或代标。操作权限矩阵：改文档维度/删除/覆盖上传/重索引 = owner 与 org_admin；维度定义/授权管理 = org_admin；建组织 = 系统管理员。**org_admin 不绕过维度可见性**（管理权与数据可见权分离），**org_admin 的文档管理列表只列出自己维度可见的文档**（与检索口径一致——issue #32 P1-4 方案 A）；**系统管理员只有管理权没有跨组织数据可见权**（确需查看走临时授权并记审计——issue #31 P1-2）。
- **维度变更是权限事件（#31 P1-5 / #32 P0-C / #34 必修 1）**：**新增维度零文档消失**（全空值放行），回填即逐篇收紧（管理页提示"待补维度"——无"先回填再启用"流程）；**停用取值 = 收紧**（视为"存在但无人被授予"，二次确认 + dry_run 影响面预估 + 审计）；**停用维度（enabled=0）不放宽**（仍参与过滤，只是上传页不再要求选值）；**退役维度（status=retired）是唯一放宽路径**——退役权限事件：影响面预估 + 二次确认 + 审计；**物理删除仅允许在无引用时**（RESTRICT）；**取值字面量不可变**（改名走"新建值 + 迁移 + 停用旧值"）。
- **成员关系与授权联动（issue #31 P1-3 / #33 P0-1）**：用户被移出组织**或成员关系过期**时级联删除该组织内授权（触发器实现）；授权行引用 `value_id`（取值只改显示名不改编码，字面量不可变）。
- **层级维度值（issue #31 P2-3，范围声明）**：**当前不支持层级维度**（如「华东区 ⊃ 上海」）——维度取值为扁平枚举；需要层级语义时用并列取值近似（授权 region=[CN]，文档挂 region=[CN]）。层级展开（用户授权按层级下沉到子值）列为演进缝（NFR-5），启用前须同步扩展 ACL 编译器的展开逻辑。
- **组织上下文统一规则（v0.4，issue #33 P1-6，写死进 D18）**：REST 用 `X-Org-Id` 请求头；MCP 以**委托 token 的 `org` claim 优先**（多组织用户的委托 token 按组织签发、claim 单值），无 claim 时读运行时在连接/传输层注入的 `X-Org-Id` 头；两者同时存在且不一致 → 400；**工具参数里的 org 一律忽略并记审计**；缺失即报错——不做任何隐式默认。
- **生效时机（已锁定）**：查询时实时展开用户维度授权为 SQL WHERE（人员调岗即时生效）；文档维度变更 = 更新维度表 + 刷 chunk 冗余过滤字段（便宜的 UPDATE，**不触发重嵌**）。
- **过滤位置红线**：引擎内下推（召回 SQL 内先过滤后取 top-k，向量路为 ACL 过滤后的行集上算距离——issue #31 P0-1），**绝不在应用层 post-trim**；**rerank 前兜底断言**（不该进模型的内容不进模型），返回前再断言一次。
- **agent 代人检索（D18）**：**委托 token（Token Exchange，RFC 8693）**——agent 用用户 token 向 IdP 换取 `aud=knowledge-lattice` 的短期委托 token（`sub`=用户、`act`=agent 标识）；本系统验签后按 `sub` 过滤、`act` 进审计；**禁止 token 原样透传（MCP 规范明令）与请求体携带权限字段**（agent 侧传来的任何权限声明一律忽略）。**降级方案（issue #32 P1-6）**：若 IdP 暂不支持 Token Exchange，采用**可信子系统**模式——agent 服务以自身服务凭证（mTLS/服务 token，须在服务白名单）调用并在请求头声明 `X-On-Behalf-Of: <user_id>`，知识库校验白名单后按声明用户计权、双身份进审计；数据模型与 D18 一致（弱化版 act/sub），后续平滑升级。**不用**"静态 token 分发给 agent"（长期凭据泄露影响全部用户）。**组织上下文不作为 LLM 可填参数**（org 从委托 token claim 或请求头获取，工具参数中的 org 一律忽略——issue #32 P1-6）。
- **权限真值源与维护（D16，v0.3 合并）**：权限拆三件事——**身份**（SSO 透传验签 + JIT 建档，不自建账号密码；静态 token 仅开发/测试）/ **授权数据**（按维度声明真值源 `grant_source`：与业务系统语义一致的维度【如法人主体、国家】只读同步，一般政策维度本地维护——管理页单点配置 + CSV 批量导入导出为主通道；同步幂等全量替换、**CSV 全量替换只清 local 授权不动 sync 授权**、失败保留旧快照并告警；业务口径→维度值走显式映射表；离职调岗经 HR/SSO 事件即时撤销）/ **执行**（永远在本系统引擎内下推）。漂移治理：季度对账 + 查询级审计回放兜底；预留同步适配器（权限中心出现时启用）。**永远不做**：查询时实时调业务系统、信任 agent 传来的权限字段。**临时授权（issue #32 P1-7）**：memberships 与授权行加 `expires_at`（权限计算过滤过期，定时清理 + 审计）——"系统管理员临时授权查看"落于此。
- owner 兜底范围见上文「owner 兜底」（检索路径无 owner 分支——#34 必修 2）；`acl_entries`（user 级临时共享）表结构保留、初版不启用。
- **组织模型（已锁定，D7 再修订）**：多组织 + **用户多组织归属**——用户账号全局唯一，经成员关系（角色 `org_admin`/`member`）属于一个或多个组织；维度定义、知识库、语料池挂组织；**维度授权按「用户 × 组织」作用域独立**（同一用户在 A 组织与 B 组织的角色、授权互不相干，各组织维度体系也不同）。系统管理员跨组织管理（建组织、指定组织管理员）。请求必须携带组织上下文（token 解析用户后按所请求组织校验成员关系），检索/上传/管理均在当前组织内执行。
- **知识库模型（已锁定，D15）**：知识库（dataset）是组织内的业务分组与管理单元（如「VAT 实务库」「费用制度库」），**不承担权限**——权限仍按文档维度 ACL；检索默认跨用户可见范围（组织内），支持按库过滤（MCP `search.datasets` / REST 参数）；对一批文档做独立管理（列表、重索引、删除）以库为单位。

### FR-5 接口面〔M0 MCP，M1 页面〕

- **MCP server**（FastMCP，**单一 server 按 docs / semantic 两组注册——D23**）：docs 组四工具（M0~M1），工具描述按「写给 LLM 看」的纪律撰写（kotaemon DocSearchTool 样板）：
  - `search(query, top_k=8 ≤20, datasets?, doc_filter?)`：完整检索配方 + 维度过滤，可限定知识库，返回带溯源字段的命中块（**top_k 服务端硬上限 20**——防一次拖库）；
  - `fetch(chunk_id, window?)`：按 chunk_id 取上下文窗口（前后 N 个 chunk）——支持 agent「先搜后读」剧本；旧版本 tombstone chunk 返回替代提示（FR-1）；
  - `upload(upload_id, dataset, dimensions, doc_id?, title?)`：投摄取任务到指定知识库——**只收不透明 `upload_id`**（凭证由 `POST /api/uploads` 签发，**绑定 sub+org+服务身份**；FR-1 三步式；路径/URL 一律不接受——SSRF 与任意文件读取防线）；覆盖更新显式带 doc_id；返回 task_id/doc_id。**工具参数不含 org 与 filename**（org 来自 token claim；filename 以声明阶段为准）；
  - `list_documents(datasets?, active_status?)`：列出权限内文档（可按库）与状态（**四字段：`active_version/active_status/pending_version/pending_status`**——在用与处理中双态并列，「先看有什么再搜」剧本）。
  - **semantic 组四工具（M2-S 起，D23；契约见 design §6.3）**：`annotate`（识别文本中的术语与业务对象）/ `search_entities`（按名称、别名、描述查实体）/ `get_entity`（实体详情 + 类型化关系展开）/ `describe_table`（透传元数据系统查表列详情）；`search` 同步新增 `entities` / `auto_entities` 参数、返回块附 `matched_entities`（FR-S3~S6）。
  - 工具描述动态注入当前组织的知识库与维度概况，**概况与 `list_documents` 的所有统计（doc_count/chunk_count 等）按调用者权限计算**——不可见文档的存在与数量不得泄露（issue #31 P1-8）；检索参数（权重/阈值类）服务端固定，不对 LLM 暴露噪音旋钮（ragflow 反面教训）。
- **REST**：upload / task status / search / admin（组织、知识库、维度、授权、用户、任务管理）；semantic（FR-S——D23，`/api/orgs/{org}/semantic/...`，design §6.2）。
- **检索测试页**（薄壳静态页，FastAPI 托管）：输入 query 看命中块与溯源，可按知识库过滤——服务上传者自查，不是聊天产品；UI 永远是薄壳，检索 API 契约先行稳定（quivr 教训）。

### FR-6 治理〔M2〕

- 审计：**按月分库**（`audit_YYYYMM.db`——当月可追加、过月封存只读、到期整文件删除；哈希链按月分段、每月首条引用上月末哈希，**月库的建表与 append-only 触发器由连接工厂在月库滚动时创建**，月库也必须走连接工厂），**覆盖查询级**（谁/何时/查了什么/返回哪些来源）；**一致性（v0.4，issue #33 P1-4）**：权限事件类审计走 **outbox**（业务库同事务写 `audit_outbox`，后台搬月库——"业务改了就一定有审计"）；查询级审计异步写，可接受丢失窗口 ≤ 5s；如需防篡改加哈希链（链头定期锚定外部）；**审计访问分级**：org_admin 本组织全量；**系统管理员仅元数据**（查询词与命中详情不含，确需看内容走审批 + 临时授权）；**保留期 12 个月**；导出/看板对查询词做关联脱敏。**语义层事件（D23）**：同步（`semantic.sync`）、构建与 YAML 合并、`restricted` 实体访问属权限事件走 outbox；`annotate` / `get_entity` 普通查询走查询级异步审计，与 docs 查询审计共用月库。
- 凭据：模型 key、内部网关凭据走环境变量/secret store，不明文存库（ragflow 反面教材）。
- 出墙：自建零 telemetry，天然干净；依赖清单上线前过一遍出墙体检。

### FR-7 评测〔M1 基线前移，M3 门禁〕

- 分层纪律：检索层（Recall@k / MRR，自算，黄金 chunk 标注的集合运算，秒级零 LLM）与响应层（faithfulness / answer_relevancy，ragas）分开度量。
- **M1 即建小型黄金集**（几十条真实/合成 query + 标注命中 chunk）并跑检索层指标——M1 的检索调参（分词/权重/阈值）必须有度量依据，不能等 M3（issue #31 P2-3）；完整黄金集与响应层指标按 M3 节奏。
- 黄金集：ragas TestsetGenerator 合成候选（双语）→ 人工抽检修正为准；**真实样例语料待用户提供（§9 待决-1）**，到位前以合成集先立基线。
- judge：内部网关 LLM；judge prompt 双语设计，上线前 ~50 条人工双评校准 judge-人一致性（中文场景硬前提）。
- M3：deepeval pytest 断言挂 CI 做变更防护；在线弱信号（引用锚点：引用不存在 ID = 幻觉证据）抽样打标。

### FR-S 业务语义层〔M2-S1~S3，D23〕

> 完整设计见 [design.md](./design.md) §4（`sem_*` DDL）/ §5.8~5.10 / §6.3；决策依据 D23（[issue #35](https://github.com/yq3/lab/issues/35)）。定位：术语层与业务对象关联统一建模为**类型化对象图**（属性图：实体 + 有类型的关系），与文档层**共享基础设施**（SQLite 连接工厂、鉴权与组织上下文、审计 outbox、worker 框架、MCP 外壳），**不共享领域模型，也不共享维度 ACL 编译器**。实体类型九种：`concept` / `system`（纯人工，YAML）、`scenario`（场景配置中心）、`template` / `template_field`（模板中心）、`report` / `report_item`（报表中心）、`table` / `column`（元数据系统，轻量节点）。

- **FR-S1 源端事实同步〔M2-S1〕**：同步适配器（`template_center` / `scenario_config` / `report_center` / `metadata`）**每日自动**拉取源端事实（名称、编码、层级、关系）——业务系统里已有的数据**不手抄进 YAML**（会过期且与源系统打架）；输出始终是"当前快照"，幂等 upsert、**只写事实列**；**删除比例保护**：快照相对库内该来源 active 实体的消失比例超阈值（默认 20%）→ run 置 `aborted_guard`、零写入、告警；**missing 宽限期**：源端消失先标 `missing`，默认 7 天后转 `retired`（关系一并 retired），防源端接口偶发空返回清空图；`metadata` 适配器**只拉被 `backed_by` / `maps_to` 引用到的表与列**（加 YAML 显式列出的），不全量镜像。每次 run 落 `sem_sync_runs` 记录 + 审计 outbox 事件 `semantic.sync`。**接入前置条件（issue #37）**：每个源系统提供能枚举「当前完整状态」的**只读查询面**——可多个分页列表接口由适配器拼装，或约定的导出文件（`fetch()` 只要求吐出全量快照记录，传输方式无关），不做增量（增量同步为 NFR-5 已登记演进缝）；**全量快照语义是删除比例保护与 missing 检测的前提，不可退让**。快照**可选携带实体的维度属性**（如模板的 region）——是否携带由业务系统按自身业务自定、**不强制**（#37 评论决策）：需要维度隔离的源在接口/导出中携带（写入实体维度绑定，供 NFR-5 实体维度 ACL 演进缝届时使用——触发前不启用），值域与本地维度不一致走显式映射表（grant_sync 同款）。源系统连接配置（endpoint/凭证/超时）进 `config.py` 的 **per-org 结构**（org→源系统实例，`fetch(org)` 据此解析目标实例），部署时配置、重启生效，不做管理页 CRUD 与 `sem_sources` 注册表（详见 design §5.8「接入前置条件」）。
- **FR-S2 YAML 覆盖层〔M2-S2〕**：人工内容（别名、缩写、定义、口径、消歧说明、示例、`l0` 标记、`sensitivity`）放 **Git YAML** 经 PR 评审（评审、可追溯、CI 校验、后续可加管理页代提 PR——真相源仍是 Git）；YAML 是**覆盖层**，按 `type:key` id 挂到同步来的源端事实上，**同步永不覆盖人工字段**（由列级分工保证：同步只写 `name/attrs_json/parent_id/status/synced_at`，从不写 `curated_json` 与 `manual/abbr` 别名）；纯人工实体只允许 `concept` / `system`；覆盖层引用未同步或已 retired 的 id → 不写入、记冲突、CI 警告，实体恢复后自动生效；`extra_relations` 可人工补源系统缺失的关系（与同步重复时以同步为准并提示可删）。**CI 校验**：JSON Schema、别名冲突（同名别名须有消歧说明或标 `match_mode: context`）、短于 2 字或常用词拦截（除非 `context` / `fuzzy_only`）、引用可解析、**L0 总 token 预算（默认 1500）**、每条必填 `owner`。
- **FR-S3 术语识别（`annotate`）〔M2-S2；模糊兜底 M2-S3〕**：三层识别——**第 1 层 AC 自动机**（确定性、必跑，服务端 P99 < 5ms）：文本规范化与 `alias_norm` 同规则（NFKC、全半角、小写）→ 最长匹配（重叠留长、等长按 `weight`）→ 歧义消解顺序「同句共现实体有 1 跳关系 → 会话焦点 `context_entities` → 调用方 `prefer_types` → 返回全部候选标 `ambiguous`」；`match_mode='context'` 的短别名仅在同句有其他确定命中且有关系时保留。**第 2 层 agentic**：第 1 层未命中但 agent 判断有业务对象时自主调 `search_entities`（不在 annotate 内执行）。**第 3 层模糊兜底**（`fuzzy=true` 才跑）：对 jieba 词性筛选的名词片段依次做拼音完全匹配、编辑距离 ≤1（仅长度 ≥4 别名）、向量近邻 top-3（阈值 0.75）——结果 `via='fuzzy'`、置信度低于第 1 层，**中间件不自动注入**，只作候选提示。**概念分级（继承 D17）**：L0 核心进 system prompt（构建期导出 `/l0`）、L1 命中时注入、L2 经工具按需查询。
- **FR-S4 关系展开（`get_entity`）〔M2-S1〕**：递归 CTE 类型化展开——`expand` 指定关系类型（可带方向后缀 `>` / `<`），**深度 ≤ 2 服务端强制**、路径防环、**高扇出截断**（每节点默认 50、上限 200，结果标 `truncated=true`）、节点上限 500（默认 200）；`include` 控制返回 `curated` / `attrs` / `aliases`。关系类型**白名单**十种（`uses` / `has_field` / `backed_by` / `maps_to` / `has_item` / `child_of` / `derived_from` / `has_column` / `refers_to` / `related_to`，含端点类型约束）由代码常量 + 触发器双重校验，关系行端点不可原地修改；**新增关系类型属 schema 变更，走迁移脚本**。
- **FR-S5 实体召回〔M2-S3〕**：`search` 新增 `entities`（实体 id 列表 ≤20）与 `auto_entities`（服务端先对 query 跑第 1 层识别）参数——种子实体经 `semantic.expand`（1 跳、默认只沿 `refers_to` / `has_field` / `maps_to` / `related_to` 低扇出关系，集合 ≤50）得实体集合，新增**实体召回路**（`sem_chunk_entities` 命中数加权：种子 1.0、扩展 0.5）与 FTS 路、向量路做 RRF 融合后进 reranker；返回块附 `matched_entities` 供 agent 解释召回原因。**ACL 不变式：实体召回路必须使用与 FTS 路、向量路同一个维度 ACL 编译产物**，语义层只提供实体 ID，不给文档可见性开任何后门（T-S8：三路并集 ⊆ 用户可见块集合）。依赖 **ingest 打标**：分块后用当前 ready 的 AC 自动机只做第 1 层打标（与块写入同事务），失败不阻断 ingest（记 warning 交 `semantic_retag` 补做）；版本切换与删块时 docs **同事务**调 `semantic.untag(doc_id, version)`，另有定时对账兜底。**默认开启条件**：docs 黄金集上开/关实体召回路的 recall@10 与 MRR **不回退**，否则保持可选参数。
- **FR-S6 表列详情透传（`describe_table`）〔M2-S1〕**：表/列详情（列类型、样例值、分区、血缘）**真相在元数据系统、不落库**——工具用服务身份实时透传，**只对已登记为 `table` 实体的表开放**（防 agent 借此枚举整个数仓）；超时默认 3s + 短期缓存 5 分钟；元数据系统不可用时返回轻量节点信息并附 `degraded=true`。元数据系统本身有表级权限时改用委托 token（RFC 8693）透传用户身份，与 D18 一致。

| 权限漂移（自建授权表与业务实际脱节，D16） | 调岗后用户仍可见旧维度文档 | 批量导出对账（季度）+ 审计回放兜底；高敏文档从严选维度；grant_sync 适配器留缝；生产前语义匹配维度切只读同步（D16） |
| deepagents/内部网关接口变更 | MCP 接入面返工 | 检索 API 契约先稳（薄壳原则）；MCP 工具面窄（docs 组四个 + semantic 组四个，参数面窄） |
| **业务语义层职责膨胀**（D23：什么都往对象图里放） | knowledge-lattice 变成大杂烩 | 模块边界规则（design §3：semantic 不 import docs 内部实现，交叉点仅标注与召回两处显式接口）；新增实体/关系类型走迁移与评审；非目标明确（GraphRAG / 图数据库 / 全量元数据镜像） |
| **语义同步故障波及服务**（源系统抖动清空图 / 同步写锁拖慢检索） | 图被大面积清空；检索劣化 | 删除比例保护（20% 中止零写入）+ missing 宽限期（7 天）；同步/重标为独立 worker 任务类型，分批 ≤1000 行、夜间错峰限速、重标最低优先级；语义故障不影响 docs 可用性（NFR-11）；必要时 `sem_*` 拆到 ATTACH 的独立库文件（接口不变） |
| **源系统无快照接口**（只读全量查询面缺失，#37） | 对应源无法接入同步，影响 M2-S 时间表 | 接入前置条件 day-one 成文给源系统（FR-S1 / design §5.8）；推动源系统排期开发；确无法满足则该源不接入（灰度），**不降低全量快照语义** |
| **需维度隔离的源系统接口未暴露维度字段**（#37 评论） | 实体维度 ACL 演进缝触发时被外部依赖卡住过渡纪律 | **宁可延迟第二区域实体接入，不可无维度字段裸同步**（裸同步 = 整区域实体按空值放行，恰是该 ACL 要防的场景）；触发时先做「是否必须进语义层」前置评估（不进 = 延续灰度零成本）；维度字段填充率骤降告警 + 管理面展示 per-source 维度覆盖（design §5.8） |
| **词典质量差**（短词/常用词误报，注入噪声误导 agent） | L1 误注入 | CI 拦截短词与常用词（除非 `context` / `fuzzy_only`）；歧义别名强制消歧说明；AC precision 门槛 ≥ 0.95；中间件只注入 confidence=1.0 的非歧义命中 |
| **人工内容无人维护**（YAML 过期、别名覆盖率低） | 识别召回下滑 | 每条 YAML 必填 `owner`；构建报告列出无人维护与孤立条目；agent 日志高频未识别词定期回流成待补别名清单 |
| **实体召回绕过维度 ACL**（语义层给文档可见性开后门） | 越权泄露 | 实体召回路强制复用 design §5.1 的 ACL 编译产物（同一编译器、同一产物）；T-S8 进越权矩阵必测 |
| **过渡期与正式版分叉**（本地 AC 与服务端行为不一致） | 切换后识别结果漂移 | YAML schema 与规范化函数抽成小 package 两端共用；切换时用评测集做对比；开关灰度 |
